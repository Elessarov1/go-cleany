# Loco Place Product Roadmap

This roadmap describes progression, not a fixed delivery calendar.

## Current state — three working verticals

Implemented:

```text
Loco Cleaning
Loco Rental
Loco Transfer
```

The next strategic question is no longer "can we add another service?". It is whether a customer who trusted one Loco service will return and delegate more tasks to Loco.

## Phase 1 — prove each vertical

Continue measuring each vertical independently:

- successful fulfillment;
- reliable supply;
- cancellation/incidents;
- average check and contribution when cost data is available;
- operational effort;
- repeat behavior where naturally recurring.

Do not mask weak economics with cross-service discounts.

## Phase 2 — Retention & Trust

Priority cross-functional capabilities:

```text
unified transaction history
Repeat / Book again
saved places / reusable customer context
same-service prefill
cross-order prefill
contextual next actions
one obvious support entry point
simple post-service quality feedback
```

Purpose: make the second successful task materially easier than the first.

## Phase 3 — Cross-service intelligence

After basic retention paths exist:

```text
smart lifecycle reminders
contextual cross-service actions
contextual benefits
cross-service conversion analytics
provider-quality signals
support operations dashboard
```

Start with deterministic, explainable rules. Do not introduce ML recommendation infrastructure before data volume justifies it.

## Phase 4 — Density

Use evidence to deepen local usage:

- partner channels with measurable first-touch attribution;
- stronger provider network and fallback capacity;
- higher repeat;
- lower failure rate;
- lower operational minutes/order;
- automation only at demonstrated bottlenecks.

## Phase 5 — expand carefully

Only then consider:

```text
additional verticals
bundles
advanced lifecycle rules
shared benefit abstraction
membership/subscription if recurring value is proven
```

A new vertical should pass a gate covering demand, supply, quality, economics, acquisition and operational load.

## Success signals

We are moving in the right direction when:

```text
completed tasks / active customer rises
30/90-day repeat rises
2+ service adoption rises
fulfillment remains high
incident rate remains low
contribution is positive
CAC payback is acceptable
ops minutes/order falls or remains controlled as volume grows
```

## Anti-roadmap

Do not make these goals by themselves:

```text
more verticals
more screens
more registrations
more generic abstractions
AI recommendations without data
subscription before repeat
provider marketplace/catalog breadth
```

The roadmap is subordinate to [manifesto.md](manifesto.md).
